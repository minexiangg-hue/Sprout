# Sprout · 芽芽工坊品牌与演示指南

版本：2026-09-29。适用于本次原型、路演、试点材料和后续产品文案。商标可用性与域名尚未核验；不得声称品牌已注册。

## 品牌核心

正式名称 **Sprout · 芽芽工坊**；中文短名“芽芽工坊”，英文短名“Sprout”。首次介绍加上“基于 Graph Code 的可视化 coding agent 创作工坊”，保留原项目出处。定位 10–16 岁孩子、亲子与社团的创作入口；8+ 探索需成人指导，年龄适用性仍待试点验证。

主口号：**把点子种出来，把每一步看明白。**

英文辅助句：**Grow an idea. Understand every step.**

“coding agent 界的 Scratch”可作口头类比，但不能成为仿造对方 logo 的理由，也不表示 Scratch 的授权、合作或认可。描述自己的能力比反复借用竞争品牌更有辨识度。

价值：给孩子可掌控的创作过程。孩子做决定，AI 协助，成人管理权限和消费。品牌承诺的是清楚的产品设计意图，不是未经证实的学习效果。

## 芽芽 IP

芽芽是一只有深绿嫩芽耳朵、浅绿圆润身体、小手脚和温和表情的创作精灵。它的职责是解释“现在在哪里”“刚才改了什么”“下一步可以试什么”。芽芽是工作中的向导，不是老师权威的替身，也不以情感依赖留住儿童。

当前矢量主资产在 [`Mascot.tsx`](../apps/web/src/studio/Mascot.tsx)。[路演 HTML](pitch-deck.html) 内联同一形象，使用原生 SVG `<symbol>` 与 `<use>`，不依赖网络图片或字体。该项目既有代码式 mascot 应继续用矢量编辑，保持形象一致。

必须保留的识别点：双片嫩芽、深色圆眼、浅绿身体、淡珊瑚腮红、短手脚。可调整姿势、大小和“开心/思考”的嘴型；不得拉伸比例、使用其他角色的外形替换、添加过度闪烁、把芽芽包装成会感到被遗弃或要求用户陪伴的生命。

“思考”用于计划生成或等待，“开心”用于作品有可验证进展。失败时配清楚的恢复建议，不责备孩子，不用惩罚/内疚情绪驱动继续使用。情绪不应暗示后台任务已经成功；任务状态以真实执行结果为准。

留白：周围至少保留角色头宽的约 1/5；小于 32px 时用嫩芽标记代替完整角色。正文旁推荐 48–80px，引导卡 120–180px，封面 280–340px。形象装饰不挤占操作说明。

## 色彩与排版

| 用途 | 颜色 | 规则 |
| --- | --- | --- |
| 主背景 Cream | `#fbfcf8` | 大面积背景，避免纯白产生过强眩光 |
| 主文字 Forest | `#26382d` | 标题、正文、重点深色面板 |
| 品牌 Lime | `#c0e98c` | 下一步、选择状态、作品进展、芽芽身体 |
| 辅助 Lavender | `#e7def6` | 计划、思考、模块分类 |
| Lavender text | `#796292` | 计划标签或辅助标注，不做大段浅色正文 |
| Muted green | `#68776a` | 次级说明，正式投影仍需足够字号 |
| 辅助 Peach | `#f3d9c7` | 假设、需要关注的边界，不等同错误红 |
| 分隔线 | `#dde5d8` | 轻边框和分区，不用厚重网格 |

亮绿与淡紫背景上使用 Forest 深色文字。不要用亮绿写在奶油底上作为关键文字。状态同时用文字和形状表达，不单靠颜色。可交互组件保留可见焦点，尊重 reduced-motion；儿童流程优先清楚的动词。

演示优先加载本地 `../apps/web/public/fonts/SproutSansSC.woff2`，字体家族 `SproutSansSC`，OFL 许可在同目录 `OFL.txt`。系统 `Inter / Noto Sans CJK SC / Noto Sans SC / PingFang SC / Microsoft YaHei / Arial` 为回退，不拉取网络字体。中文正文避免过窄字重和密集两端对齐。UI 根据设备保持可读；deck 使用 1280×720 画布，标题约 50px、卡片正文 15–21px、页脚 10–12px。投影时不要用页脚承载核心结论的关键限定：关键证据标签须在页内可见。

设计语言：圆角 15–24px、清晰模块、轻边框、大留白、少量柔和颜色。每页有一个主结论，每个模块只承担一种信息。图用于解释流程，不制造看似科学的虚构仪表。

## 语气与词汇

像尊重孩子判断力的创作伙伴：短句、具体动作、可解释原因。适合的按钮：“试一试”“改这一块”“查看发生了什么”“导出作品”“请大人帮忙设置”。错误反馈示例：“这次预览没有成功。我们先检查游戏规则这一块。”

不使用：“你太笨了”“再不来芽芽会难过”“保证学会编程”“零风险”“最强 AI”“24 个完整应用全部成功”“AR/VR 已经实现”“已全面儿童合规”。创作点不说成能完成任意任务的一口价，不能向儿童制造限时充值压力。

技术概念可以渐进展开：“模块”先解释为“作品的一部分”，文件名作为可查看的细节；专业工作台保留原始术语，避免为友好而隐藏真实能力和权限。

MiniBuild 准确表述：“自建三项纯逻辑任务，真实 Codex CLI 一次生成通过 24 项功能检查，0 修复；不代表 Studio 端到端成功率或竞品优劣。”当前图工程 context token 估计增长的反向结果应保留在评估材料中，不宣传节省 token。模型供应商成绩不能算本项目独有成绩。

竞品矩阵承认对方优势；没有调查证据时使用“待确认”，而不是叉号。Scratch 累计覆盖不能作为本项目付费 TAM；没有签约就不放客户 logo；没有一手访谈就不把设想场景包装成用户证言。

## 演示与导出

打开 [`pitch-deck.html`](pitch-deck.html) 即可播放。支持左右/上下方向键、空格、PageUp/PageDown；Home/End 跳首尾；`F` 或按钮切换全屏；触屏左右滑动。页码随 URL `#slide-N` 保留，可直接定位。按钮有中文辅助标签，隐藏页不参与屏幕阅读和焦点流。

右下角“打印 / PDF”导出全部 14 页；打印 CSS 自定义 1280×720、16:9 页面，取消浏览器页眉页脚、打开背景图形，缩放 100%。PDF 导出后应检查实际页数、文字截断、图片加载和可点击链接；原生 HTML 保留可编辑文字、表格和矢量形象。

第 5/6 页分别引用 `docs/screenshots/studio-project.png` 与 `docs/screenshots/studio-home.png`。截图缺失时显示明确标记的流程示意，不显示破图；正式路演前确认截图已加载。截图是产品证据，应来自当前原型，不用概念图冒充实际实现。截图应去除任何 API key、身份、私人文件路径或对话。

PDF 与离线拷贝要同时保留 `screenshots/` 目录，以及相对位置的 `apps/web/public/fonts/` 字体与 OFL 许可，或者由导出器内联资源；官方页脚链接依赖联网阅读，HTML 演示本身不依赖网络。讲稿、假设和问答在 [`pitch-content.md`](pitch-content.md)，财务模型在 [`business-plan.md`](business-plan.md)。

品牌/IP、logo、截图和所有文档在对外发布前应检查项目许可与第三方素材权利；此指南不构成商标检索或法律合规认证。
