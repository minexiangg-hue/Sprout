# Sprout · 芽芽工坊：市场与竞争研究

版本：2026-09-29。研究范围：让 10–16 岁孩子、亲子家庭和创作社团使用 coding agent 制作小游戏/小工具；8 岁以上的低龄探索需成人指导。当前为原型与试点准备阶段，不是已验证 PMF 的业务。来源编号见 [sources.md](sources.md)。

## 判断：切入“第一次自己改成功”，而非“第一次 AI 生成成功”

Scratch 证明孩子愿意创造互动作品，通用 AI builders 证明自然语言能成为构建界面。两者都已在向对方靠近：Scratch 在 2024 年报中提出融合生成式 AI 的 Scratch 4.0；Lovable 当前已支持课堂/社区共享额度。Sprout 的机会是把任务、项目文件和下一步修改连在同一张可理解的图上，让初学者知道“我要改角色，应该动哪一块；改完怎么验证”。这是待验证的产品判断，不能说市场存在无人竞争的空白。[S01](https://annualreport.scratchfoundation.org/) [S10](https://lovable.dev/pricing)

建议主张：**把点子种出来，把每一步看明白。** 对家长的价值是可见的创作过程；对孩子是能够独立做出第二次改变；对社团老师是可复用的活动流程和更少重复指导。不要把“会发 prompt”直接称为“学会编程”。

## 市场规模：先用可触达渠道建模

没有经过验证的付费 TAM。本次不购买黑箱行业报告，也不把全球儿童人口乘以订阅价。建议把“长期市场”讲为创意编程与 AI 创作交汇处，把首年收入讲为可检验的渠道方程。

以下全是团队规划假设，不是已签渠道、现有用户或市场统计：

| 层次 | 假设与计算 | 年度金额 / 用户 | 解释 |
| --- | --- | --- | --- |
| 首发渠道可触达池 | 100 个潜在合作节点 × 每节点 200 个去重家庭 | 20,000 家庭 | 节点名单尚待建立；不能称作行业 SAM 统计 |
| 渠道可触达收入上限情景 | 20,000 × ¥490/年 | ¥980 万/年 | 假设全部愿付费的数学上限，非预测 |
| 首年基准家庭 SOM | 30 个活跃节点 × 80 个实际触达家庭 × 25% 激活 × 20% 付费 | 120 付费家庭；¥58,800 ARR | 激活为完成首个作品及一次修改；去重后再计算 |
| 首年机构 SOM | 30 节点 × 约 1/3 转化 | 10 家机构 × ¥2,990/年 = ¥29,900 ARR | 与家庭分账；机构席位用户不得重复统计为家庭付费 |
| 首年基准合计 | 家庭 + 机构 | ¥88,700 期末 ARR | 不等于首年确认收入，不代表足以支持团队 |
| 三年可达情景 | 150 节点 × 200 家庭 × 30% 激活 × 25% 付费；另 60 机构 | 2,250 家庭 + 60 机构；¥1,281,900 ARR | 不是预测；渠道、转化、价格都需实证 |

基准首年规模很小是有用信息：若创业目标是可持续公司，必须证明渠道可复制、机构续费和更宽创作者人群，而不是用全球累计用户掩盖销售困难。

首年家庭敏感性：在 2,400 个去重触达家庭下，激活/付费分别为 15%/10%、25%/20%、40%/30% 时，付费家庭为 36、120、288，对应家庭 ARR 为 ¥17,640、¥58,800、¥141,120。没有任何一个情景已经发生。

## 研究和评估设计

1. **问题访谈**：12 家庭 + 6 老师，围绕最近一次真实创作、卡点、付费记录、放弃原因；不先展示方案诱导认可。输出匿名问题编码、原始许可记录和反例。
2. **可用性试点**：24 个亲子/社团参与者，按年龄和经验分层；交叉安排两个相近任务，随机先后顺序，比较 Sprout 与“同一模型、普通对话 + 预览”。成人介入、任务成功、耗时和成本逐次记录。样本用于形成方向，不声称统计上代表所有儿童。
3. **理解而非记忆**：完成作品后，让参与者指出控制速度/分数的模块，再在未练过的新任务上自主改一条规则。次周做迁移任务；双人评分解决争议。问卷“觉得有趣”与迁移成功分开。
4. **付费与留存**：以成人为购买者，在必要同意流程后开展有明确退款条件的试点；观察第 2/4 周的再次创作、第二个项目和真实付费。先人工验证，不先投入大额买量。

关键指标及预注册目标：首次可玩中位时间 ≤10 分钟；首次会话自主修改成功率 ≥60%；成人介入中位数 ≤2 次；第 4 周家庭留存 ≥35%；20 个以上家庭真实支付；模型成本不超过净收入 25%。这些都是决策阈值，不是已取得的结果。

## Benchmark：小众可以，挑成绩不可以

已选择并执行公共外部 [WebApp1K](https://github.com/onekq/WebApp1k) 的固定前三题诊断，其 web app 功能任务比算法竞赛更接近小工具创作。上游 commit 为 `00895306c81d5329904827b65f4a933ce3cb8746`；在生成前冻结 `tests/` 基础语料路径排序前三题，不替换失败题。样本仅为 3/1000 个任务，恰好都属于 blogging React 组件，不能代表儿童游戏或总体 benchmark。真实 `gpt-6-astra`、medium reasoning，3 次调用共 40.511 秒，每题一次生成、0 代码修复。

| 执行层次 | 实际结果 | 可得出的结论 |
| --- | --- | --- |
| 官方 latest 依赖 + 原文件布局 | 3 个 suite 加载失败，0 项断言执行 | 环境加载不兼容，不是已执行的模型功能错误 |
| 兼容依赖准备中的中间步骤 | 缺少 node-fetch peer，仍为 0 项断言 | 保留环境修复过程，不隐去失败 |
| 锁定兼容依赖 + 严格原文件布局 | 2 题通过，4 项原断言通过；1 题被 import 大小写路径阻断 | 这是严格原布局结果；阻断题不计为通过 |
| 加字节相同文件名别名的兼容诊断 | 3 题、6/6 原断言通过 | 仅解释 Linux 文件名适配后结果，不是未经适配的上游成绩 |

测试文件及生成代码主体的 SHA-256 均保持一致，没有题目替换、断言修改或代码修复。官方 prompt 故意向模型提供完整测试，不是隐藏集；Codex CLI 替代推理入口，其上下文/限制也不完全复现上游榜单生成器。该实验不经过 Studio，不建立总体通过率、教育效果或竞品领先结论，更不能宣传“WebApp1K 100%”。所有阶段与溯源见 [summary.json](../../reports/benchmarks/webapp1k/summary.json) 和 [复现说明](../../reports/benchmarks/webapp1k/README.md)。

**下一轮扩大验证计划：** 固定上游 commit、随机种子和任务清单；先按公开领域分层抽取 20 题，再接入任何模型，避免看到结果后删题。记录原始 prompt、模型版本、温度、总 token、总费用、完整失败、每题时间及生成产物。每题 3 次独立运行，同一预算比较原始 Graph Code 与 Sprout 包装层，报告 pass@1 的逐次比例、按任务聚类的区间、pass@3 和成本；只跑 20 题就明确叫“WebApp1K 20 题子集”，不能冒称全量分数。这项扩大实验尚未执行。公开测试存在污染风险，指标只说明对应功能测试。

产品本身另用 **Sprout Creative Tasks v1（自建、非公共榜单）**：接星星、电子宠物、专注计时器的初建 + 变更任务。验证浏览器行为、模块与文件对应、导出、失败反馈、跨项目状态。确定性模板演示、协议 mock、真实模型生成必须在结果中分列。模板可玩证明 demo 工程质量，不能证明模型生成能力。MiniWoB++ 测网页操作，更适合后续交互 agent 研究，因此本次不拿它作为代码能力广告。[S21](https://github.com/onekq/WebApp1k) [S22](https://github.com/Farama-Foundation/miniwob-plusplus)

路演可用表达：“我们公开测试协议与失败样例，先证明孩子能修改作品，再证明可推广。”目前没有可宣称的竞品胜出结果。

## 儿童边界会影响产品和商业路径

首发以成人管理的亲子/社团活动开展；不把一句“建议家长陪伴”当作法律豁免。在美国，COPPA 的覆盖与 13 岁以下数据处理有关；中国针对不满 14 岁个人信息有专门规则，且个人信息保护法把其列为敏感个人信息。公开产品需核实适用辖区、供应商条款、监护同意、数据删除及外发路径。Replit 的最低 13 岁条款也提示：不能把第三方成人/青少年账号能力直接包装成低龄产品。[FTC](https://www.ftc.gov/business-guidance/resources/complying-coppa-frequently-asked-questions) [网信办](https://www.cac.gov.cn/2019-08/23/c_1124913903.htm) [个人信息保护法](https://www.npc.gov.cn/WZWSREL25wYy9jMi9jMzA4MzQvMjAyMTA4L3QyMDIxMDgyMF8zMTMwODguaHRtbD9yZWY9aW1i) [Replit 条款](https://replit.com/terms-of-service)

产品建议：默认作品私有、成人控制 API 与消费、外发数据最小化、明确预览隔离范围、公开分享需成人确认、支持导出和删除；不做儿童行为广告，不收集不必要身份/人脸/声音。AI 吉祥物应是创作向导，不设计替代现实关系的依赖机制。生产版还需服务端鉴权、真实家长账户与同意记录、按地域的供应商审查；本地 demo 不可贴“已合规”标签。
