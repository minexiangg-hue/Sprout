Sprout · 芽芽工坊商业计划

把点子种出来，把每一步看明白。

日期：2026-09-29。状态：基于 Graph Code 的创作原型及创业验证方案。以下价格、获客、收入、成本和试点目标均为规划假设；没有已验证的营收、签约客户、学习效果或竞品胜出。产品运行证据与商业假设分别陈述。

1. 项目与价值

Sprout 是面向 10–16 岁孩子、亲子家庭和创作社团的可视化 coding agent 工坊。孩子描述想做的小游戏/小工具，工坊把目标拆为角色、场景、规则、声音等可解释模块，把模块关联到真实文件，再通过预览、修改、验证和导出完成创作。8 岁以上低龄用户探索采用成人指导模式。

我们保留原 Graph Code 的专业图工作台、文件处理和 coding/API 能力，以新的引导界面降低初次进入的门槛。商业价值假设是“孩子能独立完成第二次修改”，而不是只看 AI 生成一次漂亮作品。图与模块为进阶提供路径；“coding agent 界的 Scratch”用作类比，不代表与 Scratch 存在合作或授权关系。

品牌 IP“芽芽”是绿色嫩芽小精灵，承担三个具体职责：解释当前模块、显示任务进度、给出下一步选择。品牌应强调作品所有权和创作者能动性，不塑造会取代家人/朋友的陪伴关系。英文辅助口号：Grow an idea. Understand every step.

2. 问题与目标客户

当前 coding agent 能完成很多生成任务，但初学者仍需理解项目结构、开发步骤、错误和怎样描述变更。孩子有游戏点子，家长缺乏配置环境和解释报错的时间；社团老师难以同时诊断多个不同项目。这些是基于产品和竞品观察形成的问题假设，仍需用真实访谈验证。

首个付费对象是家长与课后创作社团负责人。首发场景：一节 45–60 分钟的共创活动，完成接星星、电子宠物或专注计时器，然后自主改变一条规则。先做有成人支持的创作活动，再根据实际证据决定家庭独立使用和机构部署。学校长期采购、社区市场和国际低龄直销放在后续阶段。

6. 单位经济与成本敏感性

可复算公式：

单次创作模型成本 = Σ(输入 tokens × 输入单价 + 输出 tokens × 输出单价) / 1,000,000 × 汇率假设

一个“创作会话”指完成一次有明确目标的构建或修改，成本应累计计划、生成、验证、修复各轮，不能只算最后一个响应。以下使用已读官方 API 价格作为计算锚点：Haiku 4.5 $1/$5，Sonnet 4.5 $3/$15 每百万输入/输出 tokens。不是模型选型结论。汇率统一假设 1 USD = ¥7.20，未声明为实时外汇报价；忽略缓存折扣使计算直观，图片生成和外部工具费另算。Claude API 价格

家庭版 ¥49/月，假设支付费 3%=¥1.47，托管/存储可变成本 ¥3，支持分摊 ¥4。对应贡献毛利（扣以上可变成本，未扣研发/销售/税）：轻度 ¥37.29 / 76.1%；基准 ¥34.05 / 69.5%；不设额度的高强度用户为 -¥17.79 / -36.3%。因此不能承诺无限量 agent。采用 ¥12 模型预算的满额情景贡献为 ¥28.53 / 58.2%，超额需成人主动购买，任务执行前与执行中均要约束预算。

社团版 ¥299/月，满额模型预算 ¥72，支付费 ¥8.97，托管 ¥20，支持分摊 ¥40，贡献 ¥158.03 / 52.9%。这只是模型；真实教师支持若更高，会侵蚀利润，人工教学必须独立定价。免费用户也消耗支持成本，不能从毛利计算中消失。

敏感项优先级：修复轮数 > 输出长度 > 大项目上下文 > 模型升级 > 素材生成。降低成本的方法是限定初期作品范围、模块级上下文、缓存和路由，不牺牲原专业入口通用能力。上线仪表至少按请求记录提供方、模型、tokens、现金成本、失败原因、时延和预算余额，不保存不必要儿童对话。

7. 获客与市场规模

首年假设：30 个活跃合作节点，每节点触达 80 个去重家庭，25% 完成激活，20% 激活者付费，得到 120 个付费家庭；另有 10 家付费机构。按拟议年价，期末 ARR 为 120×490 + 10×2,990 = ¥88,700。这是渠道情景，不是签约/收入预测，家庭与机构席位不重算；期末 ARR 不能直接作为首年收入。

首年推进顺序：先由团队带领 3–5 场创作活动；用匿名作品修改记录总结失败；在获得真实复购后，形成老师能独立带课的活动包；再招募更多社团/亲子渠道。家庭邀请只在成人许可下分享作品链接，不开放儿童私聊或行为广告。

三年情景：150 节点 × 200 家庭 × 30% 激活 × 25% 付费 = 2,250 家庭，另 60 机构，ARR 为 ¥1,281,900。这仍不足以自动证明风险投资规模，需要验证更大覆盖、更高复购和更多创作者用途。详细敏感性见 研究模型。

CAC 上限目标先定为家庭 ¥100、机构 ¥500，均需包括活动人力、素材和渠道返佣。基准家庭月贡献 ¥34.05，简单回收期约 2.94 月。若月流失率假设 8%，静态贡献 LTV≈¥426；15% 时≈¥227。公式忽略季节性、年付、促销和 cohort 差异，因此不用于展示“已达到 LTV/CAC”。先获得至少 3 个连续付费 cohort，再讨论稳定 LTV。

本次已有的窄实测证据： 真实 StudioService → StudioModels → Codex 路径经过 5 次调用，生成 4 模块太空计时器，0 修复，总 171.7 秒；原样产物在 Chromium sandbox iframe 中通过 10/10 行为检查。只测 1 个自选任务、浏览器使用控制时钟，不能推导总体成功率或全部 Studio UI 已通过。见 生成记录 与 浏览器记录。

公开自建 MiniBuild-3 中，真实 Codex CLI 一次生成通过 3/3 纯逻辑任务、24/24 功能用例，0 次修复；原样重放也通过。它没有经过 Studio 产品路径，不是 24 个完整应用、独立榜单或儿童效果。原图工程六个 fixture 的关系边局部性为 4/6，边界覆盖 2/2；同时，context 估计长度相比 legacy coding/review 增加 82.6% / 91.5%，因此不能宣称已经节省 token。已读取机器报告核对，完整方法和局限见 benchmark.md 与 原始 MiniBuild 结果。

公共小众 benchmark 也已执行： WebApp1K 固定上游 commit 00895306c81d5329904827b65f4a933ce3cb8746，在生成前按路径排序取 tests/ 基础语料的前三题（3/1000，均为 blogging React 组件）。显式 gpt-6-astra、medium reasoning，3 次调用共 40.511 秒，每题一次、0 代码修复。官方 latest 依赖环境首先全部加载失败、0 断言执行，不能视为模型题目失败，也不能删除这段证据。锁定兼容依赖后，严格保留原文件布局：2 题、4 项原断言通过，1 题因上游 import 大小写路径阻断。另做兼容诊断，仅增添字节相同的生成文件名别名：3 题、6/6 原断言通过。测试和生成代码主体均未编辑。

这个结果不是完整榜单分数或“WebApp1K 总体通过率 100%”：只测固定前三题，领域单一且样本过小；官方 prompt 包含完整测试；CLI 替代上游推理入口，未经过 Studio，环境适配与别名诊断都有明确偏离。没有竞争模型对照、隐藏集或总体成功率估计。原始失败、严格布局及兼容诊断分别见 summary.json 与 复现说明。

下一轮计划扩大为 WebApp1K 分层预注册子集，并用相同模型/预算比较原始 Graph Code 与 Sprout 包装层；产品评估采用三类作品和自主修改行为测试。公开失败，不把模型供应商的分数作为 Sprout 自己的成绩，不以“冷门有利”作为挑题依据。具体协议见 市场研究。

若试点出现“首次生成快，但孩子第二次无法修改”，优先改模块解释和任务设计；若 W4 留存低于目标，暂停付费买量；若满额毛利无法稳定为正，重新定额度与任务成本，再决定加价。

9. 团队、资源和六个月预算
